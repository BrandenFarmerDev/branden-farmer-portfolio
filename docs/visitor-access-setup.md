## Sessions and email semantics

Desired global, application and human-policy session durations are explicitly `24h`; `allow_authenticate_via_warp` is false globally and on each app so a device session cannot replace OTP. Existing MFA/security configuration is preserved. The emailed code is single-use and expires after **10 minutes**, not 24 hours. Cloudflare's global identity token and separately issued application tokens have independent expiry/renewal timing. A valid global identity can renew an app token, so these settings do not promise a universal exact wall-clock prompt for a new PIN across every app. Verify actual renewal/cutoff behavior before claiming it.

Cloudflare deliberately shows the same code-sent message whether or not an email is allowed. That screen, a 302 challenge or a 401 response proves neither delivery, authenticated owner success nor non-owner denial. The human enters the PIN only in a trusted browser. Never ask for codes in chat, read the inbox for them, record them, or send codes/JWTs/cookies to a remote-agent prompt.
