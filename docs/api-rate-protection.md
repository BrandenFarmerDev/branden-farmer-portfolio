# API request protection

Every portfolio HTTP fetch passes through `protectRequest` before preflight, origin checks, route/method selection, authentication, body reads or effects. Scheduled maintenance is unaffected. Native API_RATE_LIMITER admission is 300 requests per 60 seconds, approximate and per Cloudflare location, not a strict global quota. Local/preview/production namespace IDs are 2001/2002/2003; contact 1001/1005/1002 and Ask 1003/1006/1004 remain unchanged, as do daily AI quotas.

The bounded key is `api:v1:` plus SHA-256 of the canonical trusted CF-Connecting-IP literal. IPv4 requires canonical decimal octets; IPv6 uses the platform URL parser. Inputs longer than 45 characters or invalid/missing values share one sentinel bucket. Other forwarding headers, identity, method, path and query cannot select a bucket. Shared NATs and cross-zone Worker callers share capacity. This assumes direct Cloudflare ingress: workers.dev and preview URLs remain disabled, Pages serves static files, and there is no public same-zone forwarding Worker. A new forwarder requires review of this trust boundary.

Only explicit success true admits. Explicit false returns JSON 429 `rate_limited`; missing binding, malformed response, throw/rejection or a 1000ms deadline returns JSON 503 `rate_limit_unavailable`. Both include conservative Retry-After 60, normal security/no-store headers, approved-origin CORS exposure and bodyless HEAD. Owner noindex remains. The underlying binding call cannot be cancelled, but late settlement never dispatches business work; race rejection handlers and timer cleanup prevent orphan failures. Body bytes and Cal HMAC input are untouched.

The existing browser API helper performs one fetch per attempt and preserves cancellation. Readable JSON/HTML 429 and admission 503 show wait/manual-retry guidance. Opaque read errors show connection guidance; opaque mutation errors say the outcome is unconfirmed and direct users to check current state before repeating. It never automatically resubmits a mutation. Ask quota evidence responses retain their existing UI semantics. Unreadable/missing edge Retry-After uses the conservative minute guidance; it is not an exact reset promise.

## Zone WAF desired state and safe staging

`api-rate-protection-waf.json` is the canonical desired state; `npm run test:api-rate-config` validates it locally and in CI. It defines exactly ONE disabled Free-zone rule for path `/api` or prefix `/api/`, action block, characteristics cf.colo.id plus ip.src, period 10 seconds, threshold 120, mitigation 10 seconds. It intentionally has no host/method filter, bot exemption, custom response, headers or challenge. Default edge 429 may be HTML and omit CORS/Retry-After. The shared zone/IP counter couples all six API hosts, environments and NAT users; paths outside that scope receive no claim of edge protection.

Parent/operator procedure, after independent quality review:

1. Snapshot zone entrypoint and unrelated custom/US rules, Access applications/policies, IdPs and Worker bindings. Re-read immediately before each mutation; stop on drift or an occupied Free slot. Never overwrite an unowned rule or use the retired legacy endpoint.
2. Submit the exact desired request through the Rulesets API dry_run=true validation without persistence. If valid and authorized, create the absent http_ratelimit entrypoint with just the owned disabled rule, or add only that disabled rule to the existing entrypoint. Preserve unrelated rule order/content. Record IDs and full readback; compare exact owned fields and unrelated snapshots.
3. Keep enabled=false until ALL affected client fixes are released and verified. This source artifact is not evidence of a staged or active rule. Do not send deliberate live bursts, increase pressure or bypass Access for evidence. Local fixtures provide denial/mitigation/recovery evidence; actual edge enforcement/recovery needs an ordinary attributable rule event and later ordinary success. Otherwise mark it UNVERIFIED.
4. Roll back by disabling only the owned rule, then read back disabled state and unchanged unrelated controls. A created disabled/empty entrypoint can remain; do not claim byte-identical restoration. Keep the US restriction, OTP 24-hour sessions, owner authorization and exact signed Cal transport unchanged.

## Diagnostics, release conditions and recovery

At most one fixed api_admission event is emitted on guard denial/unavailability: fixed outcome plus numeric status. It contains no IP/hash, principal/token/body, arbitrary method/path/query, exception or provider response. Existing completion/error events now omit method/path. No new logging service or unbounded counters were added.

Collection remains explicitly disabled. The proposed native included-capability profile is enabled=true, redact_query_string=true, logs.enabled=true, invocation_logs=false, logs.head_sampling_rate=0.01, traces.enabled=false. The official Workers Logs documentation checked 2026-11-07 lists a Workers Free allowance of 200,000 events/day and 3-day retention, with a pricing transition announced for 2026-12-01. Recheck the actual account plan, included allowance and retention before activation; this proposal authorizes no spending. Sampling bounds ingestion proportionally, not to a fixed event count; it can miss isolated failures and is not an alerting guarantee. Before enabling a sink, verify synthetic path/query/token markers are absent from both custom logs AND automatically collected metadata, including provider subrequest metadata. Local console tests cannot prove platform privacy. Do not enable unsafe traces. No recipient, alert policy or test send is authorized by this artifact.

Release blockers: actual collected-metadata privacy evidence; actionable operator routing and exercise for sustained returned 503 (current notification policies empty; generic uncaught-exception alerts do not prove detection); live binding readback; preview/production latency; ordinary attributable edge enforcement and recovery; affected clients deployed before WAF activation. Do not claim production readiness from local tests or dry runs.

For Worker release record previous deployment IDs, use approved preview-first release, verify API_RATE_LIMITER and existing bindings without test provider effects, and restore the previous compatible Worker deployment if admission fails unexpectedly. No schema changes are involved. Do not remove the binding or fail open to recover. For limiter outages inspect native binding/configuration health and safe aggregate events; restore the correct binding or prior deployment, and independently verify before production. Routine 429 volume should be aggregated, not routed as individual alerts.
